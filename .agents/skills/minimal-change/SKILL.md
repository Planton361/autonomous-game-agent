# Minimal change

Inspect relevant code and documentation before editing. Make the smallest correct, typed, testable change that satisfies the active milestone. Preserve established behavior unless the milestone explicitly changes it; isolate side effects and avoid unrelated refactors, formatting churn, or dependency changes.

Canonical correctness, evidence, no-spoiler, and safety are never removable as “simplification.” Stop if the smallest correct change needs scope or architecture expansion.
