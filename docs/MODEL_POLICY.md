# Model policy

| Profile | Use |
| --- | --- |
| `economy` | Bounded mechanical or read-only work with simple objective verification |
| `standard` | Ordinary substantive implementation or research-processing work with clear acceptance criteria |
| `critical` | Architecture or protocol ambiguity, security/data-integrity risk, difficult diagnosis, scientific evaluation, or adversarial review |

Select an actually available model at session start. Model availability and transient
product model names are not project semantics. A model change never changes Scope,
Autonomy, authority, evidence requirements, or Definition of Done.

Use one executing agent by default. Use subagents only for independent work; writing
parallelism requires separate worktrees and disjoint paths. A reviewer is recommended for
medium risk and required for high risk; the reviewer remains read-only.

Historical task-specific model assignments remain historical evidence in their original
records and do not define current routing policy.
