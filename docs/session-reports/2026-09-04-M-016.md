## Outcome

- `XdotoolInputBackend` maps only caller-supplied primitive actions to one
  `xdotool key --clearmodifiers` argv command. `WAIT` is a no-op, and missing,
  failed, timed-out, or unavailable xdotool execution fails closed.
- `XdotoolFocusGuard` checks only the active window and exactly verifies the target title,
  optional window ID, class name, and process name. Query errors and malformed output deny focus.
- All subprocess behavior in tests is mocked. The real `InputExecutor` integration accepts a
  focused configured target and rejects a wrong target before any key command.
